# Phase 02: Build and browser verification

## Goal

Regenerate published assets and verify the promoted Ship Designer flow works in
source checks and browser smoke tests.

## Scope

- Run the standard build so generated `docs/**` output reflects source changes.
- Run the repository verifier.
- Add targeted verifier coverage only if existing browser checks do not cover
  the promoted CTA and status behavior well enough.
- Record validation and smoke-test outcomes in this plan.

## Non-goals

- Do not broaden the issue into unrelated first-run UX changes.
- Do not hand-edit generated output.
- Do not change deployment settings or GitHub Pages configuration.

## Affected files

- Potentially `tools/verify_drive_comparison_browser.mjs`
- Generated by build: `docs/index.html`, `docs/assets/js/**`
- This phase document

## Implementation steps

1. Run `npm run build`.
2. Run `npm run verify`.
3. Use a local static server and Playwright/page inspection for the specific
   Ship Designer card states.
4. If no durable automated coverage exists for the new CTA/status, add a focused
   browser verifier assertion and rerun validation.
5. Update plan outcomes with commands run and any residual risks.

## Acceptance criteria

- `npm run build` passes.
- `npm run verify` passes.
- Generated output includes the promoted CTA and summary copy.
- Browser smoke confirms the CTA opens the existing modal.
- Browser smoke confirms applying a design updates the outside-modal status.
- No generated file was edited manually.

## Validation commands

- npm run build
- npm run verify

## Manual smoke tests

1. Open the built page through a local static server.
2. Confirm the default Ship Designer card shows a text CTA and empty-state copy.
3. Open the modal from the CTA.
4. Apply a design preset and confirm the card shows an edit CTA, selected design
   name, and dry-mass summary.
5. Repeat the card text checks in Korean and English.

## Rollback risks

- Generated output may change broadly because the build republishes bundled
  assets.
- Browser verification can fail from unrelated existing fixture drift; isolate
  and document any such failure before changing source.
