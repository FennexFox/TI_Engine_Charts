# Make the existing Ship Designer discoverable as a core workflow

## Issue Target And Scope Summary

- Issue target: #32
- Title: Make the existing Ship Designer discoverable as a core workflow
- Source plan: GitHub issue body and comments, checked on 2026-06-15.
- Scope: Promote the existing Ship Designer / Dry Mass Calculator workflow in
  the left panel so first-time users can see, understand, and open it without
  knowing to click the current calculator icon.

## Strategy

- Reuse the existing dry-mass calculator modal and application flow.
- Replace the icon-only calculator affordance with a visible text CTA using
  player-facing wording.
- Add compact in-card copy that explains hull, armor, modules, and dry-mass
  assumptions are configured in Ship Designer.
- Expand the outside-modal status so the empty state and applied-template state
  are meaningful near the main simulation assumptions.
- Regenerate generated page/assets through the standard build after source
  changes.

## Known Risks And Assumptions

- The issue is about discoverability and information architecture, not new ship
  design mechanics.
- Existing Ship Designer modal behavior must continue to handle hull, armor,
  weapons, utility modules, dry mass, module effects, and simulation defaults.
- The left-panel card layout is dense; the CTA and explanatory copy must stay
  responsive without crowding mobile widths.
- Static template copy needs English replacement mappings only when the text is
  not fully managed by dynamic `localText()` updates.
