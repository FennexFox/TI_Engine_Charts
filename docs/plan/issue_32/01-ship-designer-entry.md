# Phase 01: Promote Ship Designer entry point

## Goal

Make the existing Ship Designer entry point obvious in the left panel and make
its purpose clear before the user opens the modal.

## Scope

- Update the Ship Designer card markup in
  `tools/drive_comparison_template.html`.
- Update card and CTA styles in `tools/drive_comparison_styles.css`.
- Update dynamic label/status text in
  `tools/drive_comparison_client/ui/control_state.js` and modal button text in
  `tools/drive_comparison_client/ui/dry_mass_calculator.js`.
- Add static English replacement mappings in `tools/drive_comparison_i18n.py`
  if new Korean template strings are introduced.

## Non-goals

- Do not implement a second ship designer.
- Do not change the dry-mass calculation model.
- Do not add save-file parsing, campaign-state integration, mission planning,
  or travel-time behavior.
- Do not directly edit generated `docs/**` output.

## Affected files

- `tools/drive_comparison_template.html`
- `tools/drive_comparison_styles.css`
- `tools/drive_comparison_client/ui/control_state.js`
- `tools/drive_comparison_client/ui/dry_mass_calculator.js`
- Potentially `tools/drive_comparison_i18n.py`
- Generated by build: `docs/index.html`, `docs/assets/js/**`
- This phase document

## Implementation steps

1. Replace the header calculator icon with an in-card text CTA wired to the same
   `dryMassCalcButton` handler.
2. Add concise purpose copy explaining that Ship Designer configures hull,
   armor, modules, and dry-mass assumptions.
3. Expand the empty state to explain no ship template is applied and what the
   user can do next.
4. Expand the applied-template state to include the selected design name and
   current dry mass outside the modal.
5. Keep module-effects summary and details in the same card.
6. Localize dynamic CTA/status copy through existing `localText()` paths.

## Acceptance criteria

- The Ship Designer entry point is visible without knowing to click an icon.
- The primary CTA uses text such as `Open Ship Designer` or
  `Edit Ship Design`.
- The card communicates that hull, armor, modules, and dry mass assumptions are
  configured there.
- If a template is applied, its selected name is visible outside the modal.
- If no template is applied, the empty state explains what Ship Designer can do.
- The current dry mass or applied design summary is visible near the simulation
  controls.
- Existing calculator/designer behavior continues to work.

## Validation commands

- npm run build
- npm run verify

## Manual smoke tests

1. Open the generated chart in a browser.
2. Confirm the left-panel Ship Designer card shows explanatory copy and a text
   `Open Ship Designer` CTA when no template is applied.
3. Click the CTA and confirm the existing dry-mass calculator modal opens.
4. Apply a named design preset and confirm the card changes to an edit CTA with
   the selected template name and dry mass visible outside the modal.
5. Switch between English and Korean and confirm CTA/status text localizes.
6. Check a narrow/mobile viewport for non-overlapping card text and CTA.

## Rollback risks

- Moving the button could break modal opening if the `dryMassCalcButton` id or
  setup order changes.
- Overlong status copy could crowd the control card on small screens.
- Static template strings could miss English replacements if they are not later
  overwritten by dynamic rendering.
